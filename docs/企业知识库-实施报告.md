# Implementation Report — 企业双语私域知识库与 Company-Level RAG 系统

> 非破坏式、端到端升级。基于 MatchForge 现有代码（`ai/` LangGraph 编排 + `web/` Vue3 前端 + `database/` 种子数据）扩展，未删除任何现有公司/表/集合/知识数据。

---

## 1. Architecture Summary

在现有 MatchForge 项目基础上新增 **`kb/` 知识库包** + **`api/` FastAPI 后端** + **3 个前端视图**，复用现有 `.env` / DashScope(Qwen) 配置 / Milvus 连接参数，不新增 AI 供应商。

| 层 | 实现 | 复用/降级 |
|---|---|---|
| LLM | DashScope Qwen (OpenAI 兼容, `openai` SDK) | API Key 缺失时降级为**确定性模板生成器**(业务边界内) |
| Embedding | text-embedding-v3 (1024d) | API Key 缺失时降级为**确定性 hash-bow 向量**(1024d, 同文本恒定) |
| 向量库 | 抽象 `VectorStore`: `MilvusVectorStore` + `LocalVectorStore` | Milvus 不可达时降级 Local(numpy+SQLite)；新建 `company_knowledge_chunks` 集合 |
| 主库(Source of Truth) | SQLAlchemy ORM | 默认 SQLite `data/knowledge.db`，可切 MySQL(`KB_DATABASE_URL`) |
| 公司源 | CSV 种子(优先级2) / MySQL `pc_industry`(优先级1) | MySQL 不可达自动降级 CSV |
| 后台任务 | 轻量 asyncio + SQLite 持久化 | 无 Celery/Kafka；支持断点续跑/重试/失败隔离 |
| 认证 | Bearer token + `kb_sessions` | 兼容前端 mock token；管理员 RBAC |
| 前端 | Vue3 + TS + Pinia(复用现有 axios 实例/设计 token) | 3 新视图，复用现有深色侧边栏/顶栏 |

**当前运行环境实际生效后端**: `llm=local-fallback`, `embedding=local-hashbow`, `vector_store=local`, `database=sqlite`, `demo_mode=on`（因 `.env` 中 `DASHSCOPE_API_KEY`/`EMBEDDING_API_KEY` 为空且 Docker 未启动）。所有真实路径代码已就绪，填入 Key 并启动 Docker 即自动启用 DashScope + Milvus + MySQL。

## 3. Knowledge Architecture

- **Source of Truth**：`kb_manuals`(完整 Markdown) + `kb_chunks`(切片文本) + `kb_products`(结构化) 持久化在关系库。Milvus 仅作索引层。
- **产品知识**：按 `产品系列 → 型号` 生成；每型号含 overview/specification/price/installation/procurement/FAQ。共 60 份产品手册。
- **业务知识**：按 `business_type`(来自 allowed_business_scope) 生成；每类型含 definition/applicable_customers/prerequisite/process_steps/internal_logic/communication/exceptions/FAQ。共 60 份业务手册。
- **双语**：中文与英文**独立生成、独立切片、独立 Embedding**，绝不合并为一个 chunk。`kb_chunks.language ∈ {zh,en}`。共 60 中 + 60 英手册，2490 中 + 2490 英切片。
- **Version**：`active_version` 标记当前活跃手册版本；更新时旧版本置 inactive。
- **Hash**：`source_hash`(源数据哈希，增量判断) + `content_hash`(切片文本 sha256，去重) + `chunk_uid`(全局唯一 `c{cid}-{type}-{lang}-{hash[:16]}`)。
- **Incremental Update**：`incremental_update(company_id)` 比较 `source_hash`，未变化则 idempotent skip；变化才重新生成受影响手册+切片。
- **rebuild_vector_index**：可删除 Milvus 后从 `kb_chunks`(Source of Truth) 全量重新 embedding + 索引，不丢失原始知识。

## 4. Milvus Design

- **新集合** `company_knowledge_chunks`（现有 `knowledge_chunks` 缺 `company_id/language/chunk_type` 等过滤字段，无法满足公司级 RAG → **非破坏式新建**，不动现有集合）。
- **Schema**：`chunk_uid`(PK) + `embedding`(1024d) + `company_id`(INT64) + `language` + `manual_type` + `chunk_type` + `product_model` + `business_type` + `manual_id` + `product_id` + `source_type` + `text`。
- **Index**：IVF_FLAT, COSINE, nlist=128。
- **Metadata Filter**：检索时服务端 `expr = company_id == X AND language == Y AND manual_type == Z`。
- **company_id 隔离**：检索阶段强制过滤，**禁止全库 Top-K 再让 LLM 筛选**。
- **Language Filter**：中文查询优先 `language==zh`，不足再补 `en`；英文反之。
- **Local 降级**：当前环境 Milvus 未启动，`LocalVectorStore`(numpy cosine + SQLite) 生效，4980 向量已写入。逻辑与 Milvus 一致（company_id/language 过滤）。

## 5. Knowledge Generation

**Data Source Priority**（遵循任务要求）：
1. MySQL `pc_industry.companies`（当前不可达 → 降级）
2. 项目 CSV 种子 `database/04_seed_data/02_companies_seed.csv` + `09_company_segments_seed.csv` + `01_industry_segments_seed.csv`（**当前生效**，30 家公司）
3. 公开网页（当前环境无网络，跳过）
4. AI 业务边界内补全（当前 LLM Key 缺失 → 确定性模板生成器，业务边界内）

**Business Boundary**：生成前为每家公司建立 `BusinessBoundary`（industry/primary_business/product_categories/allowed_business_scope/forbidden_expansion_scope/upstream_role/downstream_role/probable_customer_types），来自 `industry_segments`。**7 个产业环节**边界定义：被动元件/内存存储/半导体芯片/连接器线束/PCB-PCBA/采购分销/ODM-EMS。AI 生成内容不得跨边界（医疗器械公司不生成服务器等）。

**Quality Check**（`kb/quality.py`）：Business Boundary Check / Product Consistency / Language Check / Empty Check / Chunk Quality / Duplicate Check。30 家公司生成**0 issue**。

**Chunking**（`kb/chunker.py`）：语义切片，不按固定字数。产品以 `product_model` 为边界（product_overview/specification/price/installation/procurement/faq/model）；业务以 `business_type` 为边界（overview/process/sop/communication/exception/faq）。每个 chunk 自带轻量上下文 `[公司名 | 章节]`。

## 6. RAG Pipeline

- **Language Detection**：Unicode 规则（中文字符数 vs 英文字符数）。
- **Intent Classification**：factual / advisory / comparison（关键词规则 + 多公司默认比较）。
- **Factual Query**：严格依据召回知识回答；无证据则"当前企业知识库中暂无足够信息"，**禁止编造价格/参数/型号**。验证通过（GPU 显存问题不编造）。
- **Advisory Query**：知识 + LLM 推理，但不超出 `allowed_business_scope`。
- **Comparison Query**：`company_ids=[A,B]` → 分别检索 A、B（禁止 `company_id IN ALL`），各公司独立召回后汇总成对比，不相互串联归属。
- **Retrieval Trace**：每次查询记录 `request_id/user_id/company_id/query/intent/召回chunk_id/分数/来源/model` 到 `kb_rag_traces`，可经 `GET /chat/trace/{request_id}` 追溯"AI 为什么这么回答"。

## 9. Security

防 `company_id tampering` 与跨公司知识泄露：

1. **检索阶段强制隔离**（核心）：`rag.retrieve()` 向向量库传入 `company_id` 过滤，服务端 `expr = company_id == X`，**不可能**召回其他公司 chunk。已测试：向 Company 1 查询 DRAM 不返回 Company 8 的存储知识。
2. **服务端公司存在性校验**：`check_company_access` 先验证 company 存在(404)，再做权限校验(403)，不只信前端 `company_id`。
3. **Token 鉴权**：所有端点需 Bearer token(401 否则)；管理员端点需 `role=admin`(403 否则)。
4. **公司访问白名单**：`kb_company_access` 存在用户记录时强制白名单；默认 B2B 公开供应商知识对所有登录用户开放单公司查询。
5. **比较模式范围锁定**：`company_ids` 由用户明确指定，分别检索，禁止全库 `IN`，禁止 AI 自选公司加入比较。

测试验证：`test_no_cross_company_retrieval` / `test_company_a_cannot_get_company_b_knowledge` / `test_server_rejects_no_token` / `test_admin_required_for_kb_admin` / `test_whitelist_enforced_when_present` / `test_compare_only_specified_companies` 全部通过。

## 13. Known Issues & Limitations

1. **LLM/Embedding 降级**：`.env` 中 `DASHSCOPE_API_KEY`/`EMBEDDING_API_KEY` 为空 → 知识由**确定性模板生成器**生成（业务边界内、结构化、可控），Embedding 由**hash-bow** 向量替代。代码已支持真实 DashScope 路径，填入 Key 即自动启用（生成更丰富内容、语义检索更精准）。这是当前环境阻塞，非代码缺陷。
2. **向量库降级**：Docker/Milvus 未启动 → 使用 Local(numpy+SQLite) 向量库。`MilvusVectorStore` 代码已就绪，启动 Milvus 并 `pip install pymilvus` 后 `KB_VECTOR_STORE=auto` 自动切换。比较模式下过于泛化的查询在 hash-bow 下可能召回不足（具体查询正常）。
3. **MySQL 降级**：公司数据来自 CSV 种子(优先级2)，非 MySQL(优先级1)。启动 MySQL `pc_industry` 后自动切换。
4. **Demo 模式**：所有 AI 生成内容标记 `source_type=ai_generated_demo`，`KB_DEMO_MODE=true`，防止误部署为生产事实源。
5. **公司访问控制**：默认 B2B 公开策略（登录用户可查单公司）；如需限制，向 `kb_company_access` 插入白名单即强制校验。
6. **前端构建**：`vue-tsc --noEmit` 0 错误；完整 `vite build` 未在本环境运行（仅需 `npm run build`）。

## 14. Start Commands

```bash
# 0. 安装依赖（首次）
pip install -r api/requirements.txt
cd web && npm install

# 1. 数据库迁移（SQLite 自动建表；MySQL 执行迁移脚本）
#    SQLite: 运行任意 kb 命令即自动建表
#    MySQL:  mysql -h 127.0.0.1 -u matchforge -p pc_industry < database/migrations/02_kb_schema.sql
#            并设置 KB_DATABASE_URL=mysql+pymysql://matchforge:matchforge123@127.0.0.1:3306/pc_industry?charset=utf8mb4

# 2. 全量知识初始化（全部 30 家公司，中英产品+业务）
python scripts/kb_cli.py init

# 3. 后端启动
python -m uvicorn api.main:main --host 0.0.0.0 --port 8000
#   或: python -m api.main

# 4. 前端启动
cd web && npm run dev    # http://localhost:5173 (Vite 代理 /api -> :8000)

# 可选: 查看/管理
python scripts/kb_cli.py stats          # 知识库统计
python scripts/kb_cli.py capabilities   # 运行时后端
python scripts/kb_cli.py rebuild-index  # 从 Source of Truth 重建向量
```
