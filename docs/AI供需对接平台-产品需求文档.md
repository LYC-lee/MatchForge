## 1. 文档信息

> 本章结论：本文档是首期产品的执行级 PRD，只描述首期必须实现的产品需求；商业分析、技术架构细节、项目排期见关联文档，本文不重复。

首期产品定位已从宽泛的"AI 供需对接平台"收窄为"电子元器件 AI 替代料寻源助手"。远期双边平台愿景见 §4.3，不写入首期功能。

## 2. 产品一句话定义

> 本章结论：首期不是平台，而是一个单边采购寻源工具。

**采购人员输入一个元器件型号或自然语言需求，系统帮他识别规格、补全参数、推荐有依据的替代料、展示参数差异、匹配候选供应商、生成可编辑的询价单。**

---

## 3. 背景与核心问题

> 本章结论：首期只解决"缺货/停产时找可靠替代 + 生成询价单"这一段，不解决交易与物流。

中小硬件企业采购在元器件缺货、停产或降本时需要寻找替代料，当前流程依赖老员工经验，存在三个直接问题：

| 问题 | 现状后果 |
|---|---|
| 替代料靠记忆和经验 | 老员工离职即断档，新人无从下手 |
| 参数比对靠手动查 Datasheet | 一颗料比对耗时 30 分钟以上，易错漏 |
| 找有货供应商靠人脉和逐家询价 | 缺货时找不到货，询价周期长 |

---

## 4. 产品目标与非目标

### 4.1 首期目标
验证一个核心问题：**AI 能否正确结构化电子元器件采购需求，并输出采购人员认可的替代料建议？**

| 目标 | 验证方式 |
|---|---|
| 型号与关键规格识别准确 | Spike 用 20-30 条真实需求测试 |
| 替代料建议被采购认可 | ≥3/5 采购认为"有用、敢用" |
| 不推荐明显错误的替代料 | 错误替代率为核心安全指标（见 §17） |

### 4.2 非目标（首期明确不做）
- 在线交易、支付、物流、供应链金融、自营库存
- 全品类原材料（首期只做单一品类，如 MLCC）
- 完整供应商 CRM、行情预测、完整 BOM 批量优化
- 自动保证替代料一定可用（替代需采购或工程师最终确认）
- 未经供应商确认的实时库存、报价、交期承诺

> **表述红线**：未经供应商实时确认的信息，只能表述为"能力匹配"，不得表述为"确认有货 / 确认有现货"。

### 4.3 远期愿景（不在首期实现）
远期可演化为双边供需对接平台（上游线索付费、撮合、供应链金融），但**这些不是首期功能**，仅作为方向参考，不作为验收内容。

## 5. 目标用户

> 本章结论：首期服务于一个具体采购画像，而非泛化的"产业链上下游"。

**画像：李明**

| 维度 | 内容 |
|---|---|
| 企业类型 | 深圳 30-200 人中小硬件制造商 / EMS 代工 |
| 岗位 | 采购专员 / 采购主管 |
| 日常工作 | 接研发 BOM 询价、跟缺货料、找替代、比价、跟交期 |
| 当前寻源流程 | 缺货 -> 问老同事 -> 查立创/1688 -> 手动比对 Datasheet -> 逐家发询价 |
| 最痛的问题 | 停产/缺货料找不到可靠替代；参数比对耗时；不确定替代是否安全 |
| 使用触发场景 | 研发指定型号缺货停产；BOM 降本找平替；新料不知哪些供应商有货 |
| 成功标准 | 10 分钟内拿到 2-3 个有依据的替代建议 + 可直接发送的询价单 |

## 6. 三个核心使用场景

> 本章结论：首期只做这三个场景，其他场景延后。

### 场景一：完整型号缺货，寻找替代料
| 项 | 内容 |
|---|---|
| 用户背景 | 研发指定的 TMK212BJ105KG-T（0805 1uF X5R 10V MLCC）缺货 |
| 用户输入 | "TMK212BJ105KG-T 缺货，找替代" |
| 系统处理 | 识别型号 -> 解析规格 -> 查替代料表 -> 算参数差异 |
| 系统输出 | 2-3 个替代型号 + 参数差异表 + 推荐依据 + 来源 |
| 用户价值 | 不用手动查 3 份 Datasheet 比对，直接看到安全替代 |
| 失败/异常 | 型号识别失败 -> 提示补参数；无核验替代 -> 标注"仅供参考" |

### 场景二：根据参数寻找候选型号
| 项 | 内容 |
|---|---|
| 用户背景 | 知道要 0805 10uF X7R 50V MLCC，但没指定品牌型号 |
| 用户输入 | "0805 10uF X7R 50V，月用量50万，要国巨或华新科" |
| 系统处理 | 提取参数 -> 标准化 -> 匹配标准元器件库 -> 列候选型号 |
| 系统输出 | 候选型号列表 + 规格 + 品牌 + 可替代关系 |
| 用户价值 | 从模糊需求快速收敛到具体可选型号 |
| 失败/异常 | 参数不足 -> 引导补全；库中无匹配 -> 如实告知 |

### 场景三：根据确定需求生成询价单
| 项 | 内容 |
|---|---|
| 用户背景 | 已确定型号和替代，要向供应商询价 |
| 用户输入 | 选定型号 + 替代 + 用量 + 交期 + 目标供应商 |
| 系统处理 | 生成结构化 RFQ -> 用户编辑 -> 复制/发送 |
| 系统输出 | 可编辑的询价单文本（品名/规格/替代/用量/交期/请报字段） |
| 用户价值 | 不用手写询价单，一键生成可直接发送 |
| 失败/异常 | 关键字段缺失 -> 标红提示；供应商未核验 -> 提示"能力匹配非现货" |

## 7. 核心用户流程

> 本章结论：全流程任一环节置信度不足或数据缺失，系统选择"提示用户 / 进入人工审核 / 如实回答无法判断"，而非强行输出。

```
输入需求（型号/自然语言/参数）
  ↓
识别型号与参数（AI 解析 + 正则校验）
  ↓
用户确认或补充规格 ←── 缺字段时 AI 提问引导
  ↓
查看替代料及参数差异（按 5 级分类展示）
  ↓
查看候选供应商（能力匹配，非现货承诺）
  ↓
选择询价对象（可多选）
  ↓
生成并编辑询价单（可复制/导出/发送）
  ↓
保存到历史记录
```

| P7 | 简化运营审核页 | 替代料/供应商人工审核队列 |

## 9. 页面级产品需求

> 本章结论：每个页面写清目标、字段、操作、状态与跳转，可直接交设计/开发执行。

### P1 AI 寻源首页
- **页面目标**：让用户快速输入寻源需求
- **页面入口**：登录后首页 / 直接访问
- **主要模块**：输入框 + 示例 chips + 历史快捷入口
- **展示字段**：输入框占位符"输入型号或描述需求，如 TMK212BJ105KG-T 缺货找替代"
- **用户操作**：输入文本 -> 点"开始寻源" / 点示例 chip 自动填充
- **按钮**：开始寻源（主）、清空、示例
- **默认状态**：输入框为空，展示 3 个示例 chip
- **加载状态**：点击后跳转 P2，P2 内展示解析进度
- **空状态**：未输入时主按钮禁用
- **错误状态**：空输入提交 -> 输入框下红字"请输入型号或需求描述"
- **低置信度状态**：不适用
- **数据过期提示**：不适用
- **人工审核提示**：不适用
- **跳转关系**：-> P2 规格确认页

### P2 规格确认页
- **页面目标**：展示 AI 解析的规格，让用户确认或补全
- **页面入口**：P1 提交 / P3 返回修改
- **主要模块**：原始需求回显 + 解析规格表 + 缺失字段提示
- **展示字段**：型号、品牌、封装、容值/阻值、容差、温度系数、额定电压、温度范围、生命周期状态、月用量、交期
- **用户操作**：逐项确认/编辑 -> 补全缺失项 -> 点"查找替代料"
- **按钮**：查找替代料（主）、返回修改、重新解析
- **默认状态**：解析成功字段自动填充，缺失字段标黄置空
- **加载状态**：解析中显示"正在识别型号与参数…"进度条
- **空状态**：不适用
- **错误状态**：型号识别失败 -> 红色提示"未识别到有效型号，请手动填写规格"，字段进入手动编辑模式
- **低置信度状态**：字段置信度低 -> 字段旁标"?"，悬浮显示"此参数为推断，请核对"
- **数据过期提示**：不适用
- **人工审核提示**：不适用
- **跳转关系**：-> P3 替代料结果页

### P3 替代料结果页
- **页面目标**：展示有依据的替代料及参数差异
- **页面入口**：P2 确认后
- **主要模块**：原型号信息卡 + 替代型号列表 + 参数差异表（逐项）
- **展示字段**（每个替代项，见 §11.1）：替代型号、品牌、封装、关键电气参数、温度范围、容差、额定值、生命周期状态、参数一致项、参数差异项、风险项、推荐依据、来源链接、数据更新时间、是否人工核验、替代等级
- **用户操作**：查看差异 -> 选中替代 -> 点"查看供应商" / "看下一个"
- **按钮**：查看供应商（主）、对比详情、标记无用、返回
- **默认状态**：按替代等级排序（L1 完全等效优先）
- **加载状态**："正在查询替代料…"
- **空状态**：无核验替代 -> "暂无人工核验的替代料，以下为仅供参考建议（需工程师确认）"
- **错误状态**：查询失败 -> "替代料查询失败，请重试" + 重试按钮
- **低置信度状态**：置信度<0.7 的替代 -> 折叠在"仅供参考"区，置灰 + 警示图标
- **数据过期提示**：数据更新时间>180 天 -> 标"数据较旧，请核对"
- **人工审核提示**：未核验项 -> 标"待人工核验"
- **跳转关系**：-> P4 供应商匹配页

### P4 供应商匹配页
- **页面目标**：展示有相关供货能力的候选供应商
- **页面入口**：P3 选中替代后
- **主要模块**：选中的型号/替代 + 供应商列表
- **展示字段**（见 §12.2）：企业名称、经营品类、品牌覆盖、资质、地区、最小起订量、历史响应速度、数据来源、数据更新时间、是否已确认库存、是否已确认交期、是否已确认价格、匹配类型标签
- **用户操作**：勾选供应商 -> 点"生成询价单"
- **按钮**：生成询价单（主）、查看供应商详情、返回
- **默认状态**：按匹配度排序
- **加载状态**："正在匹配供应商…"
- **空状态**：无匹配 -> "暂无匹配该品类的核验供应商"
- **错误状态**：匹配失败 -> 重试
- **低置信度状态**：顶部固定提示条"以下为供应能力匹配，非实时库存承诺，最终以供应商确认为准"
- **数据过期提示**：供应商数据>90 天未更新 -> 标"信息可能过期"
- **人工审核提示**：未审核供应商不展示（status=pending 不可见）
- **跳转关系**：-> P5 询价单编辑页

### P5 询价单编辑页
- **页面目标**：生成可直接编辑/复制/发送的结构化询价单
- **页面入口**：P4 生成询价单
- **主要模块**：询价单文本编辑区 + 结构化字段区 + 收件供应商
- **展示字段**：询价单号、品名、规格、可接受替代、月用量、交期、目标价(可选)、请报字段(含税单价/交期/起订量/库存)、收件供应商
- **用户操作**：编辑字段 -> 复制文本 / 导出 / 标记发送
- **按钮**：复制、导出、保存为草稿、标记已发送
- **默认状态**：自动填充解析+替代+供应商信息
- **加载状态**："正在生成询价单…"
- **空状态**：不适用
- **错误状态**：生成失败 -> 用固定模板兜底 + 提示"自动生成失败，已用模板填充，请检查"
- **低置信度状态**：关键字段缺失 -> 标红"请补充"
- **数据过期提示**：不适用
- **人工审核提示**：不适用
- **跳转关系**：-> P6 历史记录（保存后）

### P6 历史记录页
- **页面目标**：查看/复用过往寻源与询价
- **页面入口**：首页入口 / 顶部导航
- **主要模块**：寻源记录列表 + 询价单列表（Tab 切换）
- **展示字段**：时间、原始需求、型号、替代数、供应商数、询价单状态
- **用户操作**：查看详情 / 复用生成新询价 / 删除
- **按钮**：查看、复用、删除
- **默认状态**：按时间倒序
- **加载状态**：列表骨架屏
- **空状态**："还没有寻源记录，去首页试试"
- **错误状态**：加载失败 -> 重试
- **低置信度状态**：不适用
- **数据过期提示**：不适用
- **人工审核提示**：不适用
- **跳转关系**：-> 各详情页 / P1

### P7 简化运营审核页
- **页面目标**：人工审核替代料与供应商数据
- **页面入口**：运营人员后台
- **主要模块**：替代料审核队列 + 供应商审核队列（Tab）
- **展示字段**：待审项、来源、置信度、提交时间、核验操作区
- **用户操作**：通过/驳回/标注风险 + 填来源
- **按钮**：通过、驳回、标记风险
- **默认状态**：按置信度升序（低置信优先审）
- **空状态**："无待审核项"
- **错误状态**：不适用
- **低置信度状态**：不适用（本页即处理低置信项）
- **数据过期提示**：不适用
- **人工审核提示**：本页核心
- **跳转关系**：审核结果回流到 P3/P4 展示

## 10. 核心功能需求

> 本章结论：每个 P0 功能对应一个具体用户操作和一个可验收结果（见 §17）。

### F1 需求解析
| 项 | 内容 |
|---|---|
| 功能 ID | F1 |
| 功能名称 | 自然语言需求解析 |
| 用户故事 | 作为采购，我输入型号或需求描述，系统识别出型号和关键规格，我不用手动拆解 |
| 前置条件 | 用户在 P1 输入需求 |
| 输入 | raw_query（型号 / 自然语言 / 参数） |
| 处理规则 | 型号正则前置识别 -> LLM 提取字段 -> 规则校验字段合法性；型号识别失败则进入手动填写 |
| 输出 | parsed_spec（型号/品牌/封装/容值/容差/温度系数/额定电压/用量/交期）+ missing_fields |
| 页面表现 | P2 展示解析结果，缺失字段标黄 |
| 异常情况 | 型号识别失败 -> 提示手动填写；LLM 超时 -> 正则结果兜底 |
| 数据来源 | 用户输入 + LLM + 正则规则 |
| 优先级 | P0 |
| 验收标准 | 型号识别准确率≥90%；关键字段准确率≥80%（见 §17） |

### F2 规格确认
| 项 | 内容 |
|---|---|
| 功能 ID | F2 |
| 功能名称 | 规格确认与补全 |
| 用户故事 | 作为采购，我能确认或修改规格、补全缺失参数，确保后续替代准确 |
| 前置条件 | F1 已输出 parsed_spec |
| 输入 | 用户在 P2 的确认/编辑 |
| 处理规则 | 缺失关键字段(封装/容值/温度系数/额定电压)时阻止进入 P3 并提示；低置信字段标"?" |
| 输出 | confirmed_spec |
| 页面表现 | P2 字段可编辑，缺失标黄，低置信标问号 |
| 异常情况 | 关键字段未补全 -> "查找替代料"按钮禁用 |
| 数据来源 | 用户确认 |
| 优先级 | P0 |
| 验收标准 | 关键字段遗漏率≤15%；用户能顺利完成确认 |

### F3 标准化
| 项 | 内容 |
|---|---|
| 功能 ID | F3 |

## 11. 替代料推荐规则

> 本章结论：替代料必须展示完整依据，按 5 级分类，明显不安全的直接不推荐。

### 11.1 替代料必须展示的字段
| 字段 | 说明 |
|---|---|
| 原型号 | 用户输入/识别的型号 |
| 替代型号 | 推荐的替代 |
| 品牌 | 制造商 |
| 封装 | 如 0805/0603 |
| 关键电气参数 | 容值/阻值/额定电压等 |
| 温度范围 | 如 -55~125℃ |
| 容差 | 如 ±10% |
| 额定值 | 额定电压/电流/功率 |
| 生命周期状态 | 量产/即将停产/停产 |
| 参数一致项 | 与原型号相同的参数 |
| 参数差异项 | 与原型号不同的参数 |
| 风险项 | 可能导致不兼容的差异（如电压降级、封装不同） |
| 推荐依据 | 完全等效/向上兼容/功能兼容需调整/仅供参考 |
| 来源链接或名称 | Datasheet 链接/交叉引用表/人工核验记录 |
| 数据更新时间 | 该替代数据的最后更新日期 |
| 是否人工核验 | 是/否 |

### 11.2 替代关系 5 级分类
| 等级 | 名称 | 含义 | 展示方式 |
|---|---|---|---|
| L1 | 完全等效 | 关键参数全部一致，可直接替换 | 绿色，优先展示 |
| L2 | 参数向上兼容 | 替代参数优于原型号（如电压更高），一般可直接替换 | 绿色，提示"向上兼容" |
| L3 | 功能兼容但需工程调整 | 主体兼容，个别差异需工程师评估 | 黄色，提示"需工程师确认" |
| L4 | 封装或引脚不兼容 | 电气兼容但物理不兼容，需改板 | 橙色，强提示风险 |
| L5 | 仅供参考，不建议直接替换 | 信息不足或弱关联 | 灰色，折叠在"仅供参考"区 |

### 11.3 不推荐原则
满足以下任一情况，系统选择**不推荐**而非强行输出：
- 关键参数(额定电压/封装)差异且方向不利，可能导致损坏
- 替代型号生命周期为"停产"且无等效量产料
- 信息不足以判断安全性
- 置信度<0.5 且无人工核验

> 宁可回答"暂无安全替代建议，建议联系原厂或工程师"，也不输出明显错误的替代。

## 12. 供应商匹配规则

| 字段 | 说明 |
|---|---|
| 企业名称 | - |
| 经营品类 | 主营元器件类别 |
| 品牌覆盖 | 代理/经销的品牌 |
| 资质 | ISO/IATF 等 + 是否已核验 |

## 13. AI 安全与事实边界

> 本章结论：事实型信息绝不交给 LLM 自由生成；信息不足时明确回答"无法判断"。

| 红线 | 说明 |
|---|---|
| 事实隔离 | 型号/参数/报价/库存/供应商/资质等事实型信息不得由 LLM 自由生成，走规则+字典+数据库 |
| LLM 职责边界 | LLM 只负责理解、整理、解释、生成自然语言 |
| 替代料必须有来源 | 每条替代必须有来源链接或来源名称 |
| 供应商必须来自数据库 | 禁止 LLM 编造供应商名称 |
| 必须显示数据更新时间 | 所有结果展示数据更新时间 |
| 低置信进人工审核 | 置信度<0.7 的替代进入审核队列，前端折叠 |
| 允许"无法判断" | 信息不足时系统明确回答"无法判断/暂无建议"，不强行输出 |
| 禁止虚假高置信 | 不得用高置信度掩盖数据不足 |

## 15. 两天 Spike 范围

> 本章结论：两天只验证一个问题，只做一个品类，技术方案服从验证目标，不强制六智能体/Milvus/Neo4j。

### 15.1 验证问题（唯一）
AI 能否正确结构化电子元器件采购需求，并输出采购人员认可的替代料建议？

### 15.2 范围收缩
| 项 | 范围 |
|---|---|
| 品类 | 单一品类：MLCC（首选）/ MCU / 电源管理芯片 三选一 |
| 真实需求 | 20-30 条 |
| 人工核验替代关系 | 10-20 组 |
| 候选供应商 | 10 家 |
| 标准场景 | 3 个（见 §6） |

### 15.3 简化技术流程
```
正则识别型号 -> LLM 提取字段 -> 规则校验 -> 查人工核验替代料表 -> 展示参数差异 -> 生成询价单
```

> Spike 阶段不强制使用六智能体、Milvus、Neo4j 和复杂编排。替代料表可用一张人工维护的关系表（甚至 CSV/JSON）先行验证，向量库和图谱在 MVP 再引入。**技术方案服从验证目标，不为了架构完整而过度设计。**

### 15.4 Spike 不做
- 供应商入驻系统、用户账号、交易、支付
- 多品类、完整运营后台、移动端
- 实时库存/报价/交期确认

## 17. 验收指标

> 本章结论：错误替代率是核心安全指标，宁可不给推荐也不能推荐错误替代。

| 指标 | 定义 | 计算公式 | 采集方式 | Spike 目标 | MVP 目标 |
|---|---|---|---|---|---|
| 型号识别准确率 | 正确识别型号的比例 | 正确数/总数 | 人工核对 | ≥90% | ≥95% |
| 关键字段准确率 | 关键规格字段正确率 | 正确字段数/应抽取字段数 | 人工核对 | ≥80% | ≥90% |
| 关键字段遗漏率 | 应抽未抽的比例 | 遗漏字段数/应抽取字段数 | 人工核对 | ≤15% | ≤5% |
| 替代料 Top-3 命中率 | Top-3 含采购认可替代的比例 | 命中数/需求总数 | 采购评价 | ≥70% | ≥85% |
| **错误替代率** | 推荐了明显错误/危险替代的比例 | 错误替代数/推荐总数 | 人工核对 | **≤5%** | **≤2%** |
| 来源覆盖率 | 替代料带来源的比例 | 带来源数/替代总数 | 系统统计 | 100% | 100% |
| 参数差异展示完整率 | 差异表字段完整比例 | 完整数/总数 | 人工核对 | ≥90% | ≥98% |
| RFQ 完整率 | 询价单关键字段无缺失比例 | 完整数/总数 | 系统统计 | ≥95% | ≥99% |
| 用户任务完成率 | 完成寻源->询价全流程比例 | 完成数/启动数 | 埋点 | ≥60% | ≥80% |
| 用户节省时间感知 | 用户主观感知省时 | 问卷 5 分制 | 问卷 | ≥3.5 | ≥4.0 |
| 用户再次使用意愿 | 愿意继续用 | 问卷占比 | 问卷 | ≥3/5 愿意 | ≥70% |

## 19. 风险与人工兜底

> 本章结论：每个风险有产品预防措施和人工兜底，责任边界明确。

| 风险 | 触发条件 | 影响 | 产品预防 | 人工兜底 | 责任边界 |
|---|---|---|---|---|---|
| 替代错误 | LLM 推理替代不安全 | 采购误用致损 | 5 级分类 + 风险项高亮 + 不推荐原则 | 低置信进审核队列 | 平台仅提供建议，最终由采购/工程师确认 |
| 参数缺失 | 解析遗漏关键字段 | 替代不准 | 缺失标黄 + 阻止下一步 | AI 提问引导补全 | 用户负责确认 |
| 数据过期 | 库/供应商数据久未更新 | 误导决策 | 标注更新时间 + 过期提示 | 运营定期 curate | 平台标注时效，不保证实时 |
| 供应商信息失真 | 自报信息不准 | 询价落空 | 标"供应商自报" + 能力匹配 | 资质核验 + 反馈纠错 | 平台不担保自报信息 |
| 误把能力匹配当现货 | 用户误解提示 | 期望落空 | 顶部固定提示条 + "是否已确认"字段 | - | 平台明确表述"能力匹配" |
| AI 幻觉 | LLM 编造型号/供应商 | 错误决策 | 事实隔离红线 + 来源校验 | 人工审核 | 平台对幻觉结果兜底 |
| 数据抓取合规 | 爬取立创/1688 | 法律风险 | 优先官方 API + 法务确认 | - | 需法务介入 |
| 缺少行业资源 | 无供应商/客户人脉 | 冷启动失败 | 公开数据 + 工具先行 | 人工 BD | 需引入 BD/联创 `[高风险假设]` |
| 冷启动失败 | 双边不活跃 | 项目失败 | 单边工具启动 + 窄品类 | 人工 BD 首批 | 见 §18 |

## 20. 待确认问题

> 本章结论：只保留真正阻塞下一阶段的问题，按影响从高到低排序。

1. 既有"电脑元件客服 MVP"的 RFQ 解析引擎代码/数据能否复用？--决定 Spike 起点
2. 团队是否有电子料采购圈的弱关系（校友/社群）？--决定 Spike 验证质量
3. 是否接受"下游免费、上游线索付费"的商业模式？--决定变现路径
4. 是否愿引入有行业资源的 BD/联创？--对冲最高风险
5. Spike 选哪个品类（MLCC / MCU / 电源管理）？--决定数据 curate 方向
6. 替代料数据早期是否接受人工 curate？--影响准确率与工期
7. 数据合规抓取边界是否有法务支持？--影响数据获取
8. 5 人团队角色分工（前端/后端/AI/数据/产品）？--影响排期
9. 8-12 周外是否有持续投入与少量预算？--影响 MVP 可行性
10. 是否认可"不碰交易、只做信息撮合与线索"的定位？--影响产品边界
