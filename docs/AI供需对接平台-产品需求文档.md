## 1. 项目概述

### 1.1 项目定位
面向产业链上下游的 **AI 供需对接平台**：下游采购企业用自然语言描述原材料需求，平台用 AI 解析规格、推荐替代料、匹配供应商、自动生成询价单；上游供应商获取经过分级的高质量销售线索。

**不是"再做一个 1688"**，而是 **"AI 采购助理 + 供应商线索引擎"**。平台不重做交易与物流，而是卡在"需求理解 -> 精准匹配 -> 询价生成 -> 线索分级"这一段，用 AI 把 B2B 采购中最耗人、最依赖经验的环节自动化。**先做单边工具价值，再演化出网络价值**（详见 §10）。

### 1.2 关键前提与约束（需求澄清结论）
| 维度 | 确认结果 | 对项目的影响 |
|---|---|---|
| 时间窗 | 2 天最小原型验证（非比赛） | 2 天是"8-12 周 MVP"之前的 **AI 核心能力 spike**，目标是验证楔子价值后决定 go/no-go |
| 行业资源 | 团队技术背景为主，**无行业资源** | B2B 最大命门；冷启动/首批供应商/数据真实性均需"公开数据 + 工具先行"策略 |
| 团队 | 5 人全栈，通义千问+LangGraph(Supervisor+6 智能体)+FastAPI+MySQL+Milvus+Neo4j+Vue 3 | 可 2 天搭出可运行 AI 链；复用既有"电脑元件客服 MVP"工程与 **RFQ 解析+线索分级引擎** `[待确认]` |
| 战略意图 | 真实创业方向 | 必须诚实评估可行性；风险排序以"能否活过冷启动"为准 |

> **关键战略资产** `[待确认]`：既有"电脑元件智能客服 MVP"的核心是 RFQ 解析 + 线索分级。本平台下游"需求解析->询价生成"与上游"线索推荐"几乎就是该引擎的双向泛化。若代码/数据可复用，2 天 spike 技术风险将大幅下降。见 §17 第 1 项。

### 1.3 核心价值主张
> **"用一句话描述你要买什么，AI 帮你拆成规格、找到替代料、匹配对口供应商、生成可发送的询价单--并把这条需求作为分级线索推给最合适的供应商。"**

### 1.4 与传统方案差异化
| 方案 | 能做什么 | 缺什么 | 本平台差异 |
|---|---|---|---|
| 传统 B2B 平台（1688/立创） | 海量商品搜索 | 不"理解"模糊需求、不做替代推理、不分级线索 | NL 理解 + 替代推理 + 线索分级 |
| 行业黄页/展会名录 | 供应商列表 | 无匹配、无画像、无实时性 | 智能匹配 + 画像 + 动态 |
| 采购 SaaS（ERP/SRM） | 流程与审批 | 不解决"找货找替代"前端问题 | 前端需求理解 + 寻源 |
| 搜索引擎 | 信息检索 | 结果非结构化、无行业语义、无供应商对口 | 行业知识库 + 结构化匹配 |
| 供应链平台（找钢/震坤） | 交易 + 物流 | 重自营、品类锁定、不开放匹配 | 轻交易、重匹配、开放供给 |

**楔子红线**：不是"帮你找元器件"（立创主场，红海），而是 **"帮你找替代料/缺货现货/优化 BOM"**--立创等通用搜索覆盖弱、AI 价值最显著、采购最痛的场景。

## 2. 核心痛点

### 2.1 三方痛点矩阵
| 角色 | 核心痛点 | 现状后果 | AI 可缓解程度 |
|---|---|---|---|
| 下游采购 | 需求表达不规范（型号/规格/标准混说）；找替代料靠经验；供应商比价耗时；停产/缺货料找货难 | 询价周期长、采购成本高、断料风险 | ★★★★ 高 |
| 上游供应商 | 获客成本高、线索质量差（大量无效询盘）；销售人力浪费在筛线索上；难触达精准采购需求 | 销售效率低、转化率低 | ★★★★ 高（线索分级） |
| 平台方 | 双边冷启动；数据真实性；绕过平台交易；低频导致留存差 | 难起量、难变现 | ★★ 低（需运营+机制，非纯 AI） |

### 2.2 技术内核
下游"自然语言需求 -> 精准规格 + 替代料 + 对口供应商"这一跳，与上游"无效询盘 -> 分级后的高质量线索"这一跳，是同一个 AI 引擎的两面。**这是项目的核心资产与最高壁垒起点。**

## 3. 目标客户

### 3.1 ICP 定义
**主 ICP（下游，付费潜力低但高频使用，负责拉需求）**
- 中小硬件制造商 / EMS 代工 / 采购贸易商的**采购岗**
- 月询价 ≥10 次、常遇缺货/停产/BOM 替代场景 `[假设]`
- 痛点：非标需求难表达、替代料靠老员工经验、比价慢

**次 ICP（上游，早期付费方）**
- 中小型元器件/材料**贸易商与代理商**（非原厂）
- 销售团队 ≤10 人、获客依赖展会/电话/1688、愿为有效线索付费 `[假设]`
- 痛点：线索泛滥但转化低、销售成本高

### 3.2 早期不碰
原厂（自有体系，难撬）、超大型采购方（流程长、定制化重）、钢材等巨头垄断品类。

## 4. 行业可行性分析

### 4.1 候选行业对比（5 个）
| 行业 | 市场空间 | 标准化程度 | 数据可获得性 | 客户痛点 | 付费能力 | 竞争强度 | AI 适用度 | 综合 |
|---|---|---|---|---|---|---|---|---|
| **电子元器件** | 大（万亿级含半导体流通）`[假设]` | ★★★★★ 型号/Datasheet | ★★★★★ 立创/1688/Digikey/Octopart | ★★★★ 缺货/停产替代/BOM | ★★★★ | ★★★★ 高 | ★★★★★ 型号解析+交叉引用 | **首选** |
| 包装材料 | 大 | ★★★ 材质/规格/印刷多变 | ★★☆ 1688/行业站，非结构化 | ★★★★ 找厂/打样/起订量 | ★★★ | ★★ 中低 | ★★★☆ | 次选 |
| 化工原料 | 大 | ★★★★ CAS/牌号 | ★★ 供应商封闭、报价不透明 | ★★★★ 资质/合规/替代 | ★★★★ | ★★★ | ★★★ 资质核验 | 备选（数据门槛高，无资源劣势明显） |
| 紧固件/标准件 | 中（千亿）`[假设]` | ★★★★★ GB/DIN/ISO | ★★★☆ 1688/标准件库 | ★★★ 比价/现货/小批量 | ★★ | ★★★ | ★★★★ | AI 友好但市场/付费偏弱 |
| 钢材 | 极大 | ★★★★ 牌号/规格 | ★★★★★ 钢材网报价透明 | ★★ 已被满足 | ★★★★ | ★★★★★ 极高(找钢/钢银) | ★★★ | **不推荐**（红海巨头垄断） |

### 4.2 推荐与理由
**首选电子元器件**，与"无行业资源 + 技术团队"的现实强匹配：
1. **数据公开度最高**--型号、Datasheet、交叉引用、供应商挂牌几乎全在网上，2 天 spike 无需任何人脉即可用公开数据跑通 `[高风险假设：需确认爬取合规边界]`
2. **AI 适用度最高**--型号正则解析、参数表抽取、替代料交叉引用是 LLM + 知识图谱的甜区
3. **团队有相邻经验**--电脑元件客服 MVP 沉淀的领域认知与 RFQ 引擎可迁移
4. **楔子可避开红海**--卡"替代料/缺货/BOM 优化"而非"找现货"

### 4.3 核心风险
电子料竞争激烈（立创/华强云/ICKey/Findchips）。**楔子若不够锐利会被通用搜索淹没，是整个项目最高风险点之一** `[高风险假设]`。

## 5. 商业可行性分析

### 5.1 商业模式对比（8 种）
| 模式 | 优点 | 缺点 | 适用阶段 | 风险 |
|---|---|---|---|---|
| 企业会员费 | 稳定现金流 | 价值未证前难收费 | 成长期 | 续费压力 |
| 供应商入驻费 | 门槛筛选 | 抑制供给侧 | 不宜早期 | 质量稀释 |
| 广告/推荐排名 | 变现快 | 损害中立性与信任 | 中期 | 劣币驱逐 |
| **销售线索收费** | 与上游付费意愿一致、效果可验证 | 线索质量难控 | **早期可行** | 质量纠纷 |
| 采购撮合佣金 | 与交易挂钩、价值大 | 需介入交易、绕过风险高 | 中后期 | 绕过平台 |
| **SaaS 订阅（采购/寻源工具）** | 单边可启动、不依赖双边 | 需产品深度 | **早期+长期** | 同类竞争 |
| 数据服务（行情/画像/替代料库） | 高毛利、差异化 | 采集成本、数据合规 | 中期 | 合规风险 |
| 供应链金融 | 高天花板、高粘性 | 牌照/风控/合规 | 远期 | 监管与坏账 |

### 5.2 付费/使用/受益方
| 角色 | 早期 | 中长期 |
|---|---|---|
| 使用方 | 下游采购（免费工具）+ 上游销售（接线索） | 同 + 运营/管理层 |
| 付费方 | **上游供应商**（为分级线索付费） | 上游 + 下游 SaaS 订阅 + 数据服务 |
| 受益方 | 双方均受益（下游省时、上游提效） | + 平台 + 产业链整体 |

**关键设计**：**下游免费、上游付费**。下游用免费工具聚需求（单边冷启动），上游为"分级后的高质量线索"付费，避免要求双边同时掏钱。

### 5.3 单位经济目标 `[假设/待验证]`
| 指标 | 目标 | 依据 |
|---|---|---|
| 上游客单价 | 年付 ¥3-10 万 或 ¥200-1000/条线索 | B2B 销售线索市场行情 `[假设]` |
| CAC | < 客单价/3（¥1-3 万/上游） | 回本约束 |
| 续费率 | ≥60% | B2B SaaS 及格线 |
| 注册->付费转化 | 5-10% | 行业经验值 |
| 回本周期 | <12 个月 | 现金流约束 |

### 5.4 五大难题与应对
| 难题 | 应对 |
|---|---|
| 冷启动 | **工具先行**：下游免费 AI 寻源工具单边聚需求，再以"已有真实采购需求"吸引上游 |
| 双边市场 | 先窄（单一品类电子料）后宽 |
| 绕过平台 | 收线索费而非交易佣金；提供撮合外价值（替代料库/比价/画像/管理工具）使其不舍得走 |
| 低频采购 | 用日常工具（BOM 管理/行情/询价比对）提频，不依赖交易频次 |
| 数据真实性 | 资质 OCR + 第三方核验（企查查/工商）+ 报价交叉验证 + 供应商分级 + 用户反馈纠错 |

### 5.5 早期盈利与演进路径
- **早期（0-6 月）**：销售线索收费（上游）+ 下游免费工具获客
- **中期（6-18 月）**：+ 下游 SaaS 订阅（寻源/BOM/供应商管理）+ 数据服务
- **远期（18 月+）**：+ 撮合佣金 + 供应链金融（需牌照与风控）

### 5.6 竞争壁垒（按可构建顺序）
1. **行业知识库**（替代料交叉引用表、标准字典）--最早可建、最难复制 `[核心早期壁垒]`
2. **供应商画像与采购行为数据**--随使用沉淀
3. **匹配算法**--数据飞轮驱动
4. **网络效应**--双边规模到临界点后显现（远期）

## 6. 技术可行性分析

### 6.1 整体架构
```
前端(Vue 3 + TS) -> API 网关(FastAPI)
  ├─ AI 编排(LangGraph: Supervisor + 6 子智能体)
  │   ├─ 需求解析智能体(通义千问 + 槽位抽取 + 正则校验)
  │   ├─ 标准化智能体(MySQL 标准字典)
  │   ├─ 替代料推荐智能体(Neo4j 图遍历 + LLM 推理 + 置信度)
  │   ├─ 供应商匹配智能体(Milvus 向量召回 + 规则过滤 + 排序)
  │   ├─ 询价生成智能体(LLM 结构化 RFQ)
  │   └─ 线索分级智能体(规则 + LLM 评分)
  ├─ 向量检索(Milvus 2.4: 供应商匹配 + RAG)
  ├─ 知识图谱(Neo4j: 替代料交叉引用)
  ├─ 业务 DB(MySQL 8.0) + 缓存(Redis 7: 会话/限流)
  └─ 运营后台(审核/数据治理/匹配管理)
```

### 6.2 AI 功能与技术选型映射
| 功能 | LLM | 向量检索 | 规则/正则 | 知识图谱 | 人工审核 | 说明 |
|---|---|---|---|---|---|---|
| 自然语言查询原材料 | ●● | ● | ● | | | LLM 意图+槽位抽取 |
| 参数解析 | ● | | ●● | ● | | 型号正则+参数表，LLM 兜底 |
| 分类与标准化 | ● | | ● | ●● | | 标准字典为主 |
| **供应商匹配** | ● | ●● | ● | | | 向量召回+规则过滤，**非 LLM 编造** |
| **替代料推荐** | ●● | ● | | ●● | ● | **核心亮点**，KG 交叉引用+LLM 推理+人工核验 |
| 询价需求生成 | ●● | | | | | LLM 结构化 RFQ |
| 资质核验 | | | ● | | ●● | OCR 证照+第三方 API+人工 |
| 报价对比 | | | ●● | | | 规则计算+可视化 |
| 采购风险提示 | ● | | ● | ● | ● | 规则引擎+LLM 解读 |
| 线索推荐 | ● | ●● | ● | | | 推荐算法+LLM 画像 |
| 行业知识问答 | ●● | ● | | ● | | RAG |

**核心原则**：参数/型号/报价等**事实型数据走规则+字典+DB**，绝不交给 LLM 自由生成；LLM 负责**理解、推理、生成自然语言**。这是控制幻觉的关键。

### 6.3 数据资产
| 数据类型 | 来源 | 更新方式 | 真实性验证 |
|---|---|---|---|
| 型号/规格/标准/Datasheet | 立创/Digikey/Octopart/Datasheet 库/标准网 | 定期抓取+API | 与官方 Datasheet 比对 |
| 替代料交叉引用 | Datasheet/行业交叉表/用户反馈 | 人工+LLM 辅助 | 人工核验+置信度 |
| 供应商挂牌信息 | 1688/官网/展会名录 | 抓取+供应商自维护 | 工商/企查查核验 |
| 报价/产能/交期/起订量 | 供应商主动维护+询价沉淀 | 实时+定期 | 交叉验证+标注时效 |
| 资质证照 | 供应商上传 | 入驻时 | OCR+第三方 API+人工 |
| 历史合作记录 | 平台交易/询价沉淀 | 随使用 | 平台自有 |

### 6.4 开发评估
| 项 | 评估 |
|---|---|
| 技术难度 | 中高（替代料 KG 与匹配排序最难） |
| 2 天 spike 难度 | **低-中**（仅跑通 AI 链+种子数据，不做入驻/交易） |
| 8-12 周 MVP | 可行（5 人全栈+复用 RFQ 引擎）`[假设]` |
| 主要风险 | 数据合规抓取、替代料准确性、冷启动 |

### 6.5 幻觉/错误匹配/过期数据防控
- 事实数据走规则+DB，**LLM 不可编造供应商/报价**；匹配结果可溯源到 DB 记录
- 替代料推荐**必须带置信度+来源引用**（Datasheet/交叉引用表），低置信度走人工核验
- 报价/交期等**标注更新时间，过期自动降权或隐藏**
- 资质/合规等关键决策**人工复核**
- 向用户**展示引用来源**（可解释性），建立信任

| F14 | 行情数据 | P2 | 价格走势 |
| F15 | 企业画像与线索推荐 | P2 | 上游获客 |
| F16 | 在线交易 | 不做 | 重资产，早期偏离楔子 |
| F17 | 物流仓储 | 不做 | 同上 |

### 7.2 可由人工完成的早期环节
供应商资质审核、替代料核验、首批供应商 BD 与数据 curate、线索质量抽检、客户成功。**这直接对冲"无行业资源"劣势--早期用人力补数据与信任，而非纯靠产品。**

## 8. 核心业务流程

### 8.1 下游采购侧
1. 输入原材料需求（NL/粘贴型号/BOM）
2. AI 解析需求 -> 抽取型号/规格/标准/数量/交期/可接受替代
3. 补充确认规格、标准、数量、交付要求（AI 提问式引导）
4. 获取原材料信息（结构化参数+Datasheet 引用）
5. 查看推荐供应商（按匹配度/产能/交期/位置排序）
6. 对比供应商、参数、价格、资质
7. 发起询价（AI 生成结构化 RFQ）
8. 沟通/留资/预约对接
9. 保存采购记录与供应商名单

### 8.2 上游供应商侧
1. 企业入驻与认证（资质 OCR+第三方核验+人工）
2. 上传产品/规格/产能/资质
3. 建立企业与产品画像（AI 辅助生成）
4. 获取潜在采购需求（AI 推送匹配需求）
5. 查看 AI 推荐客户（线索分级）
6. 接收询价
7. 跟进销售线索
8. 管理客户与转化（CRM 轻量）

### 8.3 平台运营侧
1. 企业审核 2. 产品/原材料分类与标准化 3. 数据治理 4. 供需匹配管理 5. 线索质量管理 6. 风险与违规审核 7. 运营数据分析

> **2 天 spike 只做 §8.1 的 1-7 步**（下游 AI 核心），上游与运营用人工/种子数据模拟。

## 11. 商业模式（早期落地版）
**早期最可行**：**上游线索收费 + 下游免费 SaaS 工具**。
- 下游免费聚需求 -> 形成真实采购需求池 -> 上游为"分级高质量线索"付费（按条或包月）
- 不碰交易，规避绕过平台与履约风险
- 单边启动，破解双边冷启动

**中长期演进**：+ 下游 SaaS 订阅 + 数据服务（替代料库/供应商画像）-> 撮合佣金 -> 供应链金融。

## 16. 2 天 Spike 行动计划（重点）

### 16.1 目标
用 2 天搭出可运行 AI 核心链，并用真实买家验证"AI 输出是否真的有用"，据此决定是否进入 8-12 周 MVP。**不碰入驻、不碰交易、不碰双边运营。**

### 16.2 Day 1：搭 AI 核心（约 12 小时）
| 时段 | 任务 | 产出 |
|---|---|---|
| 0-2h | 锁定楔子与范围：电子元器件；准备 3-5 条真实采购需求样例（如"0805 10uF X7R 50V MLCC，要国巨或华新科替代，月用量 50 万，交期 2 周"） | 需求样例集 |

| 5-9h | 搭 LangGraph 链（Supervisor+6 子智能体，复用既有 RFQ 引擎）：①需求解析->结构化规格 ②标准化 ③替代料推荐（Neo4j+LLM+置信度）④供应商匹配（Milvus 向量召回+规则过滤）⑤询价单生成 ⑥线索分级 | 可调用的 AI 链 |
| 9-11h | 套最小 UI（Vue 3 对话式+结果卡：解析规格/替代料/匹配供应商排序/生成的 RFQ），本地或简单部署 | 可演示 Demo |
| 11-12h | 自测 3-5 条样例，修明显 bug，准备验证脚本 | 验证就绪 |

### 16.3 Day 2：真实买家验证 + 决策（约 10 小时）
| 时段 | 任务 | 产出 |
|---|---|---|
| 0-3h | 招募 5-8 位真实采购（校友/硬件社群/1688 买家群/冷启触达），安排测试 | 测试名单 |
| 3-7h | 每人输入 2-3 条**真实当前采购需求**，观察 AI 解析/替代/匹配/询价是否准确有用；记录每条成功与失败 | 测试记录 |
| 7-9h | 汇总指标：AI 解析准确率、替代料相关性（人工评）、供应商匹配相关性、"愿用/愿付费"信号、失败模式清单 | 验证报告 |

**必须产出**：①可演示 AI Demo；②真实买家定性反馈与准确率数据；③Go/No-Go 决策及下一步理由。
**不碰**：供应商入驻系统、交易、支付、完整运营后台、多品类、移动端。

## 17. 初步结论
- **2 天 spike：值得做**。低成本验证 AI 核心价值，且可复用既有 RFQ 引擎，技术风险低。
- **8-12 周 MVP：有条件值得**。条件：①spike 验证 AI 准确率≥80% 且≥3/5 真实买家认可；②能在 MVP 前明确"无行业资源下的首批供应商获取"路径。
- **长期双边市场：高风险**。无行业资源是结构性劣势，不建议在单边工具验证+首批真实交易跑通前 All in。
- **策略定调**：**工具先行（下游免费 AI 寻源聚需求），网络后至（上游线索付费变现）**。用"单边工具价值"对冲"双边冷启动+无资源"两大命门。

## 18. 三个关键问题的结论

### ① 这个项目是否值得做？
- **2 天 spike：值得**--低成本、可复用既有引擎、能快速证伪 AI 楔子。
- **8-12 周 MVP：有条件值得**--前提是 spike 过关 + 拿出"无资源下获取首批供应商"的可执行方案。
- **完整双边平台：暂不值得 All in**--无行业资源 + B2B 双边冷启动是结构性硬伤，需用"工具先行"先活过冷启动再谈平台。
- **净结论**：值得花 2 天验证 AI 楔子；不值得现在就投入做完整双边平台。把项目从"做平台"降维成"先做一个采购方爱用的 AI 寻源工具"，是当前最理性的路径。

### ② 最适合从哪个行业、客户群体、使用场景切入？
- **行业**：电子元器件（首选）--数据公开度与 AI 适用度双最高，且与团队既有经验相邻。
- **客户群体**：中小硬件制造商/EMS/采购贸易商的**采购岗**（高频、对替代料/现货敏感、有 BOM 优化需求）。
- **使用场景**：采购用自然语言（或粘贴型号/BOM）描述需求 -> AI 解析规格 -> **推荐替代/等效料**（核心 AI 亮点）-> 匹配有现货/产能的供应商 -> 生成结构化询价单并发起；同时把该需求作为**分级线索**推给上游。
- **楔子红线**：必须卡在"**替代料/缺货/BOM 优化**"，绝不做"找现货通用搜索"--后者是立创主场，必死。

### ③ 整个时间周期为两天，我们该怎么做？
详见 **§16 两天 Spike 行动计划**。一句话概括：**Day 1 搭可运行 AI 核心链（需求解析->替代料->供应商匹配->询价生成->线索分级）+30-50 家种子供应商+20-50 组替代料交叉引用；Day 2 招募 5-8 位真实采购验证，以"≥3/5 买家愿用 且 解析准确率≥80%"为 Go/No-Go 标准。** 两天只验证 AI 楔子，不碰双边运营与交易。
