# 电脑全链路数据库建设执行计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

> 如果当前目标是 16 小时内快速交付最小可用数据库底座，请优先执行 `电脑全链路数据库16小时冲刺执行计划.md`。本文保留为 8-12 周的长期建设路线。

**Goal:** 用 8-12 周建立一套可支撑 MatchForge AI 寻源、产业链公司库、物料规格库、供应商匹配、RFQ 询价和后续 BOM 风险分析的数据库基础。

**Architecture:** 以 MySQL 作为业务事实源，优先沉淀结构化数据；用 Neo4j 承载产业链关系、替代料关系和兼容关系；用 Milvus 承载物料规格、供应商能力和文档知识的向量检索；用 MinIO 存放 Datasheet、资质、认证和检测报告。

**Tech Stack:** MySQL 8.0、Neo4j、Milvus、Redis、MinIO、FastAPI、SQLAlchemy、Vue 3。

---

## 1. 执行原则

- 先做能支撑产品闭环的数据，不先做完整 ERP/MES。
- 先沉淀“产业链公司 + 物料 + 供应商 + RFQ + 替代关系”，再扩展 BOM、采购、库存、制造、质量。
- 所有 AI 推荐结果必须能追溯到数据库记录、文件来源或人工审核记录。
- MySQL 是事实源，Neo4j 和 Milvus 从 MySQL 或文件数据异步同步。
- 每个阶段都要产出可检查的数据样例、字段定义和验收标准。

| 阶段 | 周期 | 目标 | 主要交付物 |
|---|---:|---|---|

## 3. Phase 0：数据范围与标准定义

**目标：** 明确第一版数据库到底收什么、不收什么，避免一开始做成大而全系统。

**建议周期：** 3-5 个工作日。

**任务清单：**

- [ ] 确定首批覆盖品类：建议从 `MLCC、电阻、电感、连接器、PCB、SSD、内存、散热、电源适配器` 中选择 3-5 个。
- [ ] 确定首批覆盖产业环节：建议从 `元器件、模组、分销、ODM、EMS、检测认证` 开始。
- [ ] 输出公司库字段标准：公司名称、别名、国家/地区、官网、产业环节、主营品类、客户类型、数据来源、更新时间。
- [ ] 输出物料库字段标准：型号、品牌、品类、参数 JSON、生命周期、认证、Datasheet、来源、更新时间。
- [ ] 输出供应商能力字段标准：供应商、覆盖品类、代理品牌、MOQ、交期、地区、资质、数据来源、审核状态。
- [ ] 输出数据可信度标准：官方来源、授权分销来源、平台自报、第三方聚合、人工核验。

**交付物：**

- `数据实体清单`
- `字段字典`
- `首批采集品类清单`
- `数据来源优先级规则`

**验收标准：**

- 能清楚回答第一版数据库收哪些实体、哪些字段、哪些数据源。
- 每个字段都有中文名、英文名、类型、是否必填、示例值。
- 团队一致确认首批品类不超过 5 个。

## 4. Phase 1：产业链公司库

**目标：** 建立电脑产业链公司的基础数据库，支撑产业链地图、公司检索和后续供应商匹配。

**建议周期：** 1-2 周。

**优先公司范围：**

- 上游元器件：Intel、AMD、NVIDIA、Samsung、SK hynix、Micron、Murata、TDK、Yageo、Walsin、BOE、立讯精密。
- 中游制造：Foxconn、Quanta、Compal、Wistron、Inventec、Pegatron、Flex、Jabil、BYD Electronics。
- 分销与供应链：Arrow、Avnet、Digi-Key、Mouser、立创商城、华强电子网、云汉芯城、中电港。
- 检测认证：SGS、UL、Intertek、TUV Rheinland、华测检测、广电计量。

**任务清单：**

- [ ] 建立 `industry_segments` 数据：原材料、芯片、存储、PCB、被动元件、连接器、显示、电池、散热、结构件、ODM、EMS、检测认证、渠道、售后。
- [ ] 建立 `companies` 数据：首批录入 100-200 家代表公司。
- [ ] 建立 `company_segments` 关系：一家公司可以属于多个产业环节。
- [ ] 建立 `company_categories` 关系：公司覆盖哪些产品品类。
- [ ] 给每条公司数据标注来源：官网、年报、授权名录、公开资料、人工整理。
- [ ] 给每家公司设置可信度等级：A 官方确认、B 多来源交叉验证、C 单一公开来源、D 待核验。

**交付物：**

- 首批公司库 CSV 或数据库记录。
- 产业环节字典。
- 公司-环节关系表。
- 公司数据来源记录。

**验收标准：**

- 至少录入 100 家公司。
- 每家公司至少有 `名称、国家/地区、产业环节、主营品类、数据来源`。
- 每家公司至少绑定 1 个产业环节。
- 重点公司不能只有中文名，需保留英文名或官方名。

## 5. Phase 2：物料与规格库

**目标：** 建立可供 AI 解析、标准化、搜索和匹配的物料基础库。

**建议周期：** 2 周。

**优先品类：**

- 被动元件：MLCC、电阻、电感。
- 电脑关键模组：SSD、DRAM、显示屏、电池、散热器。
- 连接类：Type-C、HDMI、内存插槽、板对板连接器。

**任务清单：**

- [ ] 建立 `categories` 品类树：电脑整机、主板、芯片、存储、被动元件、连接器、显示、电源、散热、结构件。
- [ ] 建立 `spec_definitions`：不同品类对应不同规格字段。
- [ ] 建立 `parts` 物料主表：型号、品牌、品类、生命周期、数据来源、更新时间。
- [ ] 建立 `part_specs` 或 JSON 参数字段：按品类保存规格。
- [ ] 建立 `documents` 文件表：Datasheet、认证、检测报告、图片。
- [ ] 建立 `part_documents` 关系：物料关联哪些文件。
- [ ] 首批录入 500-1000 条物料数据，优先从 MLCC、SSD、DRAM、连接器开始。
- [ ] 对关键字段做标准化：容量、电压、封装、接口、尺寸、温度、功率。

**交付物：**

- 品类树。
- 规格字段定义。
- 首批物料库。
- Datasheet 文件索引。

**验收标准：**

- 至少 3 个品类具备完整规格字段定义。
- 至少 500 条物料记录可被搜索。
- 每条物料有型号、品牌、品类、关键参数、来源。
- 至少 100 条物料关联 Datasheet 或官方页面。

## 6. Phase 3：替代料与兼容关系

**目标：** 支撑“缺货找替代”和“BOM 风险分析”的核心能力。

**建议周期：** 1-2 周。

**任务清单：**

- [ ] 定义替代等级：L1 完全等效、L2 跨品牌兼容、L3 参数有差异、L4 需工程评估、L5 仅参考。
- [ ] 建立 `part_alternatives`：原型号、替代型号、替代等级、参数差异、风险说明、来源、审核状态。
- [ ] 建立 `compatibility_rules`：接口兼容、封装兼容、电气参数约束、尺寸约束。
- [ ] 建立 `review_tasks`：低置信度替代关系进入人工审核队列。
- [ ] 首批整理 100-200 组替代关系，优先 MLCC、电阻、电感和连接器。
- [ ] 将审核通过的替代关系同步到 Neo4j，支持多跳查询。

**交付物：**

- 替代等级规则。
- 替代关系表。
- 人工审核队列。
- Neo4j 替代关系图谱样例。

**验收标准：**

- 至少 100 组替代关系。
- 每组替代关系都有来源和风险说明。
- L3 及以下替代必须展示参数差异。
- 未审核或低置信替代不得作为“安全替代”直接推荐。

## 7. Phase 4：供应商能力与 RFQ 数据

**目标：** 让 AI 推荐可以从“找到物料”进一步走到“找到谁可能供货”和“生成询价”。

**建议周期：** 2 周。

**任务清单：**

- [ ] 建立 `suppliers`：供应商主体、地区、审核状态、资质。
- [ ] 建立 `supplier_capabilities`：供应商覆盖品类、品牌、MOQ、交期、服务区域。
- [ ] 建立 `supplier_qualifications`：营业执照、ISO、代理资质、授权证书。
- [ ] 建立 `rfqs`：采购需求、目标物料、可接受替代、数量、交期、目标价。
- [ ] 建立 `rfq_suppliers`：一个 RFQ 发给哪些供应商。
- [ ] 建立 `quotations`：供应商报价、价格、交期、MOQ、有效期、备注。
- [ ] 建立 `leads`：供应商视角的商机线索和评分。
- [ ] 首批录入 50-100 家供应商能力数据。

**交付物：**

- 供应商能力库。
- RFQ 数据模型。
- 报价数据模型。
- 线索分级规则。

**验收标准：**

- 至少 50 家供应商有能力标签。
- 每家供应商至少绑定 1 个品类和 1 个地区。
- RFQ 能关联多个目标供应商。
- 报价记录能反向追溯到 RFQ、供应商和物料。

## 8. Phase 5：BOM 风险分析

**目标：** 让用户可以上传或录入电脑 BOM，系统识别缺料、风险料、可替代料和候选供应商。

**建议周期：** 2 周。

**任务清单：**

- [ ] 建立 `pc_products`：整机产品、配置版本、生命周期、目标市场。
- [ ] 建立 `boms`：BOM 编号、版本、状态、所属整机。
- [ ] 建立 `bom_items`：物料型号、用量、位号、关键等级、是否允许替代。
- [ ] 建立 BOM 导入模板：支持 Excel/CSV 的列定义。
- [ ] 建立 `bom_risk_results`：缺料风险、生命周期风险、单一供应商风险、价格波动风险。
- [ ] 建立 `bom_alternative_suggestions`：每个风险物料对应推荐替代料。
- [ ] 建立 `bom_supplier_matches`：每个风险物料对应候选供应商。
- [ ] 用 3-5 份样例 BOM 跑通分析流程。

**交付物：**

- 整机产品表。
- BOM 表和 BOM 明细表。
- BOM 导入模板。
- BOM 风险分析结果。

**验收标准：**

- 能导入一份包含 50-200 行的 BOM。
- 能识别 BOM 中已存在于物料库的型号。
- 能标出缺失物料、停产风险、无替代风险。
- 至少对 20 个物料给出候选供应商或替代建议。

## 9. Phase 6：采购、库存、制造、质量的最小扩展

**目标：** 为后续全链路平台预留 ERP/MES/QMS 数据基础，但不在第一版做复杂流程。

**建议周期：** 2 周。

**任务清单：**

- [ ] 建立 `purchase_orders`：采购订单、供应商、状态、金额、交期。
- [ ] 建立 `purchase_order_items`：采购物料、数量、单价、交付日期。
- [ ] 建立 `inventory_batches`：仓库、批次、数量、供应商、入库日期。
- [ ] 建立 `serial_numbers`：整机或关键部件序列号。
- [ ] 建立 `work_orders`：生产工单、BOM、计划数量、状态。
- [ ] 建立 `quality_records`：IQC、IPQC、OQC、FCT、Burn-in、RMA 的统一记录。
- [ ] 明确哪些字段只是预留，哪些字段进入实际产品流程。

**交付物：**

- 采购订单最小模型。
- 库存批次最小模型。
- 工单最小模型。
- 质量记录最小模型。

**验收标准：**

- 能从物料追溯到供应商、RFQ、报价、采购记录。
- 能从 BOM 追溯到物料、供应商和风险结果。
- 能为后续生产追溯预留序列号和批次关系。

## 14. 风险与控制

| 风险 | 表现 | 控制方式 |
|---|---|---|
| 范围过大 | 一开始想覆盖所有电脑零件和所有流程 | 首批只选 3-5 个品类 |
| 数据不可信 | AI 推荐无法解释来源 | 每条关键数据必须记录来源和可信度 |
| 替代料错误 | 推荐不安全替代 | L3 及以下必须展示风险，低置信进入人工审核 |
| 供应商数据过期 | 交期、MOQ、资质不准 | 设置更新时间和过期降权规则 |
| 多库存储不一致 | MySQL、Neo4j、Milvus 数据不同步 | MySQL 做事实源，异步同步带版本号和同步时间 |
| 太早做重型流程 | 变成 ERP/MES，拖慢 MVP | Phase 6 之前不做复杂审批流和生产排程 |

## 16. 推荐的第一版产品闭环

第一版不要做完整全链路，只做下面这个闭环：

```text
用户输入物料需求或上传 BOM
  -> 系统识别物料和规格
  -> 从物料库找到标准型号
  -> 从替代关系库找到可替代型号
  -> 从供应商能力库匹配候选供应商
  -> 生成 RFQ
  -> 记录报价
  -> 回流供应商能力和价格数据
```

这个闭环能直接服务 MatchForge 当前定位，也能自然积累后续做采购、库存、制造和质量追溯所需的数据。
