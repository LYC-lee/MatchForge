# AI 对话产品阵营 风格对标调研

> 调研日期：2026-07-17 ｜ 标杆：ChatGPT、Claude、Perplexity、Kimi（月之暗面）
> 聚焦：消息排版、流式输出反馈、引用与来源展示、思考/工具调用折叠、输入区演进，及其向 AI 寻源对话的迁移。

---

## 各标杆风格画像

### ChatGPT（OpenAI）

**视觉语言要点**

- 品牌层：2025 年 2 月完成首次品牌重塑，启用定制字体 **OpenAI Sans**（与 ABC Dinamo 合作），色板以中性灰 + 蓝调为主，刻意呈现"开放、理性、不过度个性"的平台气质（来源：[Wallpaper*, 2025-02-04](https://www.wallpaper.com/tech/openai-has-undergone-its-first-ever-rebrand-giving-fresh-life-to-chatgpt-interactions)、[Loftlyy 品牌库, 2026-03-14](https://www.loftlyy.com/en/openai)）。
- 消息排版：**AI 回复无气泡**——直接以文档式排版（Markdown 标题/列表/代码块带复制按钮/表格）落在画布上；用户消息则反相处理为右侧浅灰胶囊气泡。消息流单列限宽约 **768px**（Claude 约 768、Perplexity 约 720，超出即不可读）（来源：[setproduct AI chat 设计指南, 2026-05-29](https://www.setproduct.com/blog/ai-chat-interface-ui-design)）。
- 头像语义：去人格化——AI 侧用品牌 sparkle 符号或直接省略头像，把视觉重量让给内容本身；头像只在用户侧承担身份标识。
- 流式输出：早期为闪烁方块光标，现演进为**无可见光标的平滑逐 token 渲染**；排队期（200ms–2s）用脉动圆点占位，**禁用假进度条**（来源：setproduct, 同上）。回复期间输入区发送键变为「停止」，结束后换「重新生成」，多版本回复以**横向轮播**保留，供对比与复制。
- 思考/工具调用：o 系列推理折叠为一行**耗时摘要**（"Thought for X seconds"样式），点击展开；搜索等工具调用以朴素语言的状态行呈现（"Searching the web"），默认折叠、可展开审计。行业共识：推理块从"流式展开"到"完成折叠"必须有**平滑动画**，瞬间消失会被用户感知为 bug（来源：[Kilocode issue #7110, 2026-03-16](https://github.com/Kilo-Org/kilocode/issues/7110)、[AI UX Playground Progress Steps, 2026-07-11](https://aiuxplayground.com/pattern/status-steps)）。
- 引用：内联来源 chip + 悬停 popover + Sources 侧栏三层结构（来源：[AI UX Playground Citations pattern, 2026-07-10](https://aiuxplayground.com/pattern/citations)）。
- 输入区：居中大圆角胶囊（圆角约 24–28px），附件、模型选择、语音集成于框内；`Cmd/Ctrl+Enter` 发送、`Shift+Enter` 换行为事实标准（来源：setproduct, 同上）。

**值得 MatchForge 借鉴的模式**

1. **「文档式对话」排版**：AI 回复去气泡 + 720–768px 限宽 + 用户消息弱气泡。寻源对话的回复是规格清单、替代料表、供应商对比表——本质是文档而非聊天，气泡只会挤压表格宽度、制造视觉噪声。
2. **推理摘要行**：一行「已思考 X 秒 · 已检索 N 家供应商」+ 可展开明细。寻源工作流（规格确认→替代料→匹配→RFQ）天然多步骤，耗时摘要行既安抚等待又保留审计入口。
3. **回复多版本轮播**：重新生成的报价单/推荐方案不覆盖旧版，横向切换对比——直接对应采购"多方案比稿"的心智。

### Claude（Anthropic）

**视觉语言要点**

- 色彩：品牌主色**赤陶色 #da7756** + 米白/奶油背景 + 深黑正文，是 AI 市场被蓝紫垄断下**唯一的暖色系选择**，传递"温暖、接地、人文"的信任信号（来源：[rar.design《Claude 介面設計解析》, 2026-04-01](https://rar.design/posts/claude-interface-design-philosophy)）。
- 字体三层策略：Logo 用定制衬线 Galaxie Copernicus；品牌标题用 Styrene B；**对话正文用 `ui-serif` 系统堆栈（Georgia → Cambria → Times New Roman）**。Anthropic 开发者文档甚至建议避免 Arial/Inter——"太泛濫，会产生廉价 AI 感"（来源：同上）。衬线体在心理上传递"深思熟虑、有份量"，提升用户对内容质量的感知。
- 密度与留白：宽松行距、大量留白、无气泡、米白纸面质感，刻意让阅读速度放慢。
- 动效：克制的流式渲染 + 平滑折叠，不做炫技动效，品牌表达靠色彩与字体而非动画。
- 交互哲学「**Good Friction**」：面对协作者而非工具时，刻意保留好的摩擦力——Plan Mode 下复杂任务**先核对计划、确认方向，再执行**，而非零摩擦秒出结果（来源：同上，Joel Lewenstein 访谈）。

**值得 MatchForge 借鉴的模式**

1. **暖色差异化破局**：蓝紫渐变（#6366f1→#8b5cf6）正是 Claude 刻意避开的"同质化雷区"。MatchForge 可在深色主题内引入一档暖色（琥珀/陶土系）作为关键行动色或信任标记色，在"冷色科技感"的 B2B 工具海洋中建立辨识度。
2. **Plan Mode 的 Good Friction**：寻源不是闲聊——AI 在生成 RFQ 前**先输出规格确认清单让用户逐项确认**，主动引入"好的摩擦力"，比一口气生成错误的报价单更符合 B2B 风险控制心智。这是流程设计，也是信任设计。
3. **字体即信任**：正文排版的"份量感"影响可信度感知。中文场景无法照搬 ui-serif（宋体系屏显效果差），但可借鉴其思路：正文与数据用不同字重/字族分层，避免全局单一系统字体带来的"廉价模板感"。

### Perplexity

**视觉语言要点**

- 色彩：品牌重塑后采用**深青（teal）色系**，取代早期浅蓝背景以增加对比与专业成熟度；TEAL-1 #E9F4F8 用于官网 hero 背景，标志性渐变蓝仅限 logo 菱形符号与关键高亮，克制使用以放大识别度（来源：[Perplexity 品牌指南 PDF, brandfetch](https://asset.brandfetch.io/id-KlPkbGF/idnL1nru5G.pdf)）。
- 布局：答案页单列（约 720px）+ 标签页结构（Answer / Images / Links），信息密度高于 Claude、低于传统搜索结果页，排版为"可扫读的报告"。
- 引用体系（核心资产）：**分层信任栈**——
  1. **内联域名 chip**：句末挂 publisher-first 圆角 chip（如 `foxsports +2`），`+N` 表示多来源，扫读时即可见证据；
  2. **折叠研究步骤**："Completed 2 steps"展开为"Searching the web / Checking current predictions"——**用用户语言而非 API 名词命名步骤**；
  3. **答案栏来源汇总行**：favicon 堆叠 + "10 sources"，与复制/分享同层级，一眼展示证据广度；
  4. **chip popover**：点击 chip 原地弹出标题/摘要/1-N 翻页，快速核查不离开上下文；
  5. **Links tab 全量审计**：每条来源为卡片（favicon、URL、标题、摘要、缩略图），与答案平级（来源：[AI UX Playground Perplexity Citations 拆解, 2026-06-15](https://aiuxplayground.com/teardowns/perplexity/citations)）。
- 信任闭环：负面反馈中「Wrong sources」为独立选项（与"不准确"分开路由）；**选中文段可 "Check sources"** 局部核查单条论断，不必重跑整个查询（来源：同上）。

**值得 MatchForge 借鉴的模式**

1. **分层溯源信任栈 → 采购依据溯源**：这是全场对 MatchForge 价值最高的模式。AI 寻源的每条关键论断（"该替代料兼容 3.3V 供电"、"该供应商近 90 天交期 7 天"、"参考价 ¥12.5/pcs"）都应挂**内联来源 chip**（规格书 / 历史订单 / 供应商档案），答案栏加"N 个依据"汇总行，另设审计视图列出全部依据卡片。采购决策需要留痕，这正是 Perplexity 信任栈的 B2B 转译。
2. **步骤命名用业务语言**：折叠步骤写"正在核对规格参数 → 正在匹配在库供应商"，而非"调用 match_supplier API"。采购用户不是开发者。
3. **选段级核查**：用户高亮报价单中某一行即可"核对该条依据"，把信任 UX 从页面级做到论断级——对应采购审计单条参数的真实场景。

### Kimi（月之暗面）

**视觉语言要点**

- 色彩与整体：浅色主题 + 蓝色品牌主色 + 大量圆角卡片，气质干净、工具感强，贴合中文大众用户的"效率助手"定位；与 ChatGPT 的中性灰、Claude 的暖陶、Perplexity 的深青形成第四种路线——**轻量蓝白工具风**。
- 输入区演进（标杆意义最大）：输入框「+」已成为**能力总入口**——上传文件/图片、常用语（可复用提示词模板）、专业数据库、技能（Skill）、联网开关全部收进一个菜单；移动端输入框上方设 **Taskbar** 一键开启 Agent 任务（来源：[Kimi 帮助中心·新手入门指南, 2026-07-13](https://www.kimi.com/zh-cn/help/new-user-guide/overview)）。
- 模式显性化：**联网搜索 / 快速 / 思考三种会话模式用户可显式切换**，官方甚至提示"简单文档问答可全部关闭"——把成本与延迟的选择权交给用户（来源：同上）。
- 思考与搜索过程：思考模式支持"多轮思考与搜索"，过程步骤化展示后折叠；Agent 集群场景下工具调用（最高 1500 次并行、100+ 子代理）以进度化方式呈现（来源：同上）。
- 文件能力深度整合：单文件 100M、最多 50 个文件、支持 PDF/Word/Excel/PPT/图片/视频——输入区附件不是附属功能而是主流程（来源：同上）。

**值得 MatchForge 借鉴的模式**

1. **输入区「+」= 寻源能力入口**：采购对话的输入区应承担同样的总入口角色——上传 BOM 表 / 规格书 / 历史 RFQ、插入常用询价模板、切换"快速询价 / 深度寻源"模式。Kimi 证明了中文用户对"+号聚合菜单"的学习成本几乎为零。
2. **模式显性切换**：「快速报价」（秒回、低精度）与「深度寻源」（多轮检索、供应商尽调）作为用户可控档位，配合延迟预期管理——比隐藏式自动路由更适合 B2B 的可预期性要求。
3. **常用语模板机制**：采购有高频重复句式（"按上次条款询价"、"该料有没有国产替代"），内置可复用提示词模板直接提升留存。

## 对 MatchForge 的迁移建议汇总

按优先级排列（现状差距 → 改成什么）：

**P0-1 消息排版文档化（对标 ChatGPT/Claude）**
现状差距：AI 回复若采用气泡卡片式排版，在深色主题下气泡边框（#2b3140）+ 背景分档会让规格表、对比表被多层盒子嵌套，可读性差 → 改为 **AI 回复无气泡、单列限宽 720–768px、文档式 Markdown 排版**；用户消息保留右侧弱气泡（低饱和填充、无边框）以维持对话方向感。头像去人格化：AI 侧用品牌符号，用户侧用企业/角色标识。

**P0-2 推理与工具调用的"耗时摘要行 + 平滑折叠"（对标 ChatGPT/Kimi）**
现状差距：动效无降级、过程反馈缺失 → 寻源工作流的每一步（规格确认→替代料→匹配→报价）渲染为**朴素业务语言的状态行**（"正在匹配在库供应商…"），完成后平滑折叠为「已完成 4 步 · 用时 X 秒」摘要行，可展开审计。折叠/展开必须有过渡动画并支持 `prefers-reduced-motion` 降级——避免"过程瞬间消失"的断裂感（行业公认反模式）。

**P0-3 消息状态完整性（对标 ChatGPT）**
现状差距：错误与中断处理薄弱、文案有开发者痕迹 → 补全七态：排队（脉动点占位）/ 思考 / 流式 / 完成 / 错误（**写明原因 + 单一修复动作**，禁止"Something went wrong"式笼统文案）/ 重生成（旧版入轮播不删除）/ 已停止（保留半截输出 + 继续/重生成双选项）。

**P1-1 分层溯源信任栈（对标 Perplexity）——寻源对话的核心信任基建**
现状差距：AI 给出的替代料推荐与报价无依据展示 → 关键论断挂**内联来源 chip**（显示依据类型：规格书/历史价/供应商档案，+N 表多依据）；回复底栏加 favicon/图标堆叠 + "N 条依据"汇总行；chip 点击原地 popover 快查；另设审计视图（平级 tab 或侧栏）列出全部依据卡片。配套：负面反馈增设「依据有误」独立选项；支持选中单条论断局部核查。

**P1-2 输入区能力总入口化（对标 Kimi）**
现状差距：输入区功能单一 → 「+」菜单聚合：上传 BOM/规格书/历史 RFQ、常用询价模板、模式切换（快速询价 / 深度寻源）；`Ctrl+Enter` 发送、`Shift+Enter` 换行；多行自动生长至上限后内部滚动。

**P1-3 Plan Mode 式好摩擦（对标 Claude）**
现状差距：AI 寻源一键到底，错误规格直接流入 RFQ → 在生成报价单前插入**规格确认卡点**：AI 输出结构化确认清单（封装/耐压/数量/交期），用户逐项确认或修改后才进入匹配与报价。流程上"慢一步"，信任上"进一步"。

**P2-1 暖色点缀破局蓝紫同质化（对标 Claude/Perplexity）**
现状差距：主色靛蓝 #6366f1 + 渐变 #6366f1→#8b5cf6 正是 AI 产品最拥挤的色区，且与浅色遗留样式并存 → 保留深色主题骨架，但将**关键行动色或信任标记色替换/补充为暖色一档**（琥珀/陶土系，如 #d97706~#da7756 区间），用于"已核实依据""供应商已认证"等信任信号；同时收敛硬编码色值入令牌。参考 Perplexity 的克制策略：品牌渐变仅限 logo 与关键高亮，不大面积铺。

**P2-2 排版分层避免"廉价模板感"（对标 Claude）**
现状差距：全局单一系统字体栈、字号层级服务功能不服务信任 → 正文/数据/辅助三层字体策略：正文保持系统无衬线（中文屏显最优），数字与价格用等宽或 tabular-nums 保证表格对齐，关键结论加字重对比。中文场景**不要**照搬 Claude 的衬线正文——宋体系在数据密集表格中可读性差。

**应避的坑**
不要为消费级"陪伴感/呼吸感"牺牲密度与效率：Claude 式大留白和慢节奏适合 C 端思考伙伴，但 MatchForge 是数据密集的 B2B 工具，密度应对标 Perplexity 的"可扫读报告"而非 Claude 的"书页"；同样，打字机光标、人格化头像、拟人语气这类 C 端暖场手段在采购场景只会稀释专业信任。
