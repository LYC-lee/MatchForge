# MatchForge 演示场景前端计划

日期: 2026-07-16
分支: codex/demo-scenario-frontend

## 目标

实现演示登录和悬浮演示控制台前端。用户在登录页选择 6 家演示主视角企业进入系统，登录后固定绑定该企业，不再提供系统内企业切换。demo 模式显示悬浮控制台，调用后端演示接口推进订单、库存、缺件、RFQ、报价、补货和替代料阶段。

## 已完成

1. 新建独立 worktree 与分支。
2. 阅读 Vue 路由、登录页、auth store、企业 API、驾驶舱、RFQ、供应商页面。
3. 新增 6 家演示企业前端白名单，不把环境企业放入登录下拉。
4. auth store 支持 demo 企业绑定、demo token、本地固定企业视角。
5. 侧边栏移除企业切换下拉，改为展示当前绑定企业。
6. 新增 demo API client，路径对齐 `/api/v1/demo/*`。
7. 新增悬浮演示控制台，支持展开/收起、八个阶段按钮、事件日志、接口错误提示。
8. 控制台动作成功后广播刷新信号，驾驶舱、产品 BOM、RFQ、供应商工作台/线索页接入刷新。
9. 修正路由守卫异步 session 校验。
10. 前端 build 已通过。

## 未完成/未验证

1. 后端 demo 接口尚未在当前前端分支内验证真实响应结构，前端已按建议路径和容错字段接入。
2. 未启动真实后端做端到端点击验证。
3. 真实账号的企业绑定依赖后端 `/auth/me` 或登录响应返回 `company_id`；如果后端暂不返回，前端会沿用本地已有绑定或默认企业。

## 当前风险

1. 后端分支未合并时，悬浮控制台会显示“演示接口暂不可用”，不会生成纯前端假数据。
2. 若后端事件字段命名与当前兼容字段完全不同，事件列表可能只显示默认摘要，需要后续按后端最终 schema 微调。
3. demo token 名称当前使用 `demo-token`，需与后端兼容逻辑保持一致。

## 下一步建议

1. 后端 demo 分支合并后做一次端到端演示按钮验证。
2. 后端 `/auth/me` 补齐真实账号 `company_id/company_name`，前端即可完全固定真实账号企业视角。
3. 根据最终 demo event schema 精简控制台事件格式。
