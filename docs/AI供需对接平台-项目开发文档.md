# AI 供需对接平台 - 项目开发文档

| 项 | 内容 |
|---|---|
| 文档版本 | v1.1 |
| 编写日期 | 2026-07-14 |
| 团队规模 | 5 人全栈 |
| 技术栈 | 通义千问 DashScope + LangGraph(Supervisor+6 智能体) + FastAPI + MySQL 8.0 + Milvus 2.4 + Neo4j + Redis 7 + Vue 3 |
| 技术栈来源 | 复用既有"电脑元件客服 MVP"工程，改造业务语义 `[待确认]` |
| 关联文档 | [产品需求文档](AI供需对接平台-产品需求文档.md)、[系统架构文档](AI供需对接平台-系统架构文档.md) |
| 当前阶段 | Phase 0：2 天 AI Spike（2026-07-15 ~ 2026-07-16） |

> 本文档解决"谁做什么、何时做、如何协作"。技术栈沿用既有工程，Spike 主要是**改造 6 个智能体的业务语义 + 接入电子元器件数据**，而非从零搭基建。

---

## 1. 开发目标

| 阶段 | 目标 | 验收 |
|---|---|---|
| **2 天 Spike** | 搭可运行 AI 核心链 + 用真实买家验证楔子 | AI 解析准确率≥80% 且 ≥3/5 买家愿用 -> Go/No-Go |
| **8-12 周 MVP** | 双边最小产品 + 试点跑通 | 首批真实询价/线索/付费信号 |

---

## 2. 团队配置与角色分工（5 人）

| 角色 | 代号 | 主要职责 | 不做 |
|---|---|---|---|
| 产品 + 前端 | **P1** | 需求细化、UI/UX、Vue 3 对话界面+结果卡、买家验证协调 | 后端、AI 算法 |
| 后端工程师 | **P2** | FastAPI 服务、MySQL Schema、API、询价/线索管理、部署 | AI 智能体内部、前端 |
| AI 工程师（核心） | **P3** | LangGraph Supervisor + 6 子智能体实现与调优、Prompt、幻觉防控 | 数据 curate、前端 |
| 数据/知识库工程师 | **P4** | 种子供应商 curate、**Neo4j 替代料图**、Milvus 索引、标准字典 | 业务 API、AI 智能体逻辑 |
| 全栈 + DevOps + BD | **P5** | 部署运维、端到端联调、招募真实采购、客户深访、运营后台 | 单一模块深做 |

**关键依赖关系**：
```
P4(数据: MySQL+Neo4j+Milvus) ──喂料──▶ P3(6 智能体) ──输出──▶ P2(API封装) ──对接──▶ P1(Vue 前端)
                                                                       ▲
P5(部署+联调+BD) ───────────────────贯穿全程────────────────────────────┘
```
> **P3 是关键路径**，P4 必须先于 P3 提供种子数据（供应商入 MySQL+Milvus、替代料入 Neo4j、字典入 MySQL），P2/P1 先定 API 契约再并行开发。

## 3. 2 天 Spike 开发计划（小时级 + 每人任务）

### Day 1：搭 AI 核心（约 12 小时）

| 时段 | P1 产品+前端 | P2 后端 | P3 AI（关键路径） | P4 数据 | P5 DevOps+BD |
|---|---|---|---|---|---|
| 0-2h | PRD 细化、界面线框（对话框+结果卡）、定 API 契约 | MySQL Schema 建表、FastAPI 骨架、OpenAPI 契约 | 通义千问 DashScope 接入验证、LangGraph Supervisor 骨架与 State 定义 | 锁定数据源、curate 起步（1688/立创挂牌） | DevOps 环境（docker-compose：mysql+milvus+neo4j+redis+minio）、仓库与 CI |
| 2-5h | 对话界面 + SSE 流式过程展示组件 | 实现 `/procure` 等接口壳 + SSE | 需求解析 + 标准化 智能体 | curate **30-50 家**供应商入 MySQL+Milvus | 买家招募启动（发邀请、排期 5-8 人） |
| 5-9h | 结果卡组件（规格/替代料/供应商/RFQ/线索） | 接 P3 链、询价/线索存 MySQL | 替代料推荐（Neo4j）+ 供应商匹配（Milvus）智能体 | **20-50 组**替代料交叉引用入 Neo4j + Milvus 索引 + 标准字典 | 端到端联调支持、Bug 修复 |
| 9-11h | 联调、样式打磨 | 部署（docker-compose 起服务） | 询价生成 + 线索分级 智能体 + Prompt 调优 | 数据质量校验、补漏 | 确认买家测试名单与时间 |
| 11-12h | 自测 3-5 条样例 | 服务稳定性检查 | 自测准确率、修明显 Bug | 备用数据准备 | 验证脚本就绪 |

**Day 1 交付物**：可演示 Demo（NL 输入 -> SSE 流式过程 -> 结果卡 -> 可生成 RFQ），种子数据（MySQL+Milvus+Neo4j）就绪。

### Day 2：真实买家验证 + 决策（约 10 小时）

| 时段 | 主导 | 全员配合 |
|---|---|---|
| 0-3h | P5 | 买家招募到位、测试环境就绪 |
| 3-7h | P5 + P1 | 每位买家输入 2-3 条**真实采购需求**；P1 陪测收反馈；P3 监控 AI 输出记失败模式；P4 数据补漏；P2 保服务稳定 |
| 7-9h | P3 + P1 | 汇总指标：解析准确率、替代料相关性（人工评）、匹配相关性、"愿用/愿付费"信号、失败模式清单 |
| 9-10h | 全员 | **Go/No-Go 决策会**：≥3/5 买家愿用 且 准确率≥80% -> GO；否则调楔子或止损 |

**Day 2 交付物**：①验证报告（准确率+定性反馈+失败模式）；②Go/No-Go 决策及理由。

### Spike 期明确不做
供应商入驻系统、交易/支付、完整运营后台、多品类、移动端、用户账号体系。

## 7. 协作规范

| 项 | 规范 |
|---|---|
| 代码仓库 | 单仓多目录：`/web` `/api` `/ai` `/data` `/deploy` |
| 分支策略 | `main` 受保护；`feature/*` 分支开发；PR 至少 1 人 review |
| API 契约 | FastAPI 自动生成 OpenAPI；**前后端先定 Schema 再并行开发**，禁口头约定 |
| 代码规范 | Python: ruff + black；TS: eslint + prettier；提交前本地 lint |
| 评审 | Spike 期每日 2 次 standup（早 9:00 / 晚 18:00）；MVP 期每日 1 次 |
| 文档 | 接口/Schema 变更同步更新架构文档；PR 描述含变更说明 |
| LLM 调用 | 所有 LLM 调用经 LangFuse 记录 trace，便于排查准确率问题 |
| 模型配置 | LLM/Embedding 走 `.env`，支持任意 OpenAI 兼容服务；Key 不入库 |
| 数据变更 | 种子数据/Neo4j 图变更走 PR，记录来源与核验状态 |

## 9. 验收标准（Definition of Done）

**Spike 期 DoD**：
- [ ] 6 个子智能体全部可运行，端到端 `/procure` 跑通
- [ ] 种子数据：≥30 家供应商（MySQL+Milvus）+ ≥20 组替代料（Neo4j）
- [ ] 前端可演示完整动线（输入->SSE 流式->结果卡->RFQ）
- [ ] 至少 5 位真实买家完成测试并留有反馈记录
- [ ] 准确率与"愿用"信号数据汇总完成
- [ ] Go/No-Go 决策文档输出

**MVP 期 DoD（每个 Sprint）**：
- [ ] 代码 review 通过、单测覆盖核心逻辑
- [ ] demo/staging 环境可运行、验收场景跑通
- [ ] 接口与架构文档同步更新
- [ ] 无 P0/P1 缺陷遗留

## 10. 开发风险与应对

| 风险 | 概率 | 影响 | 应对 |
|---|---|---|---|
| P3 AI 准确率不达预期 | 高 | 高 | 人工核验兜底 + Prompt 迭代 + few-shot；不达标字段走人工确认 |
| P4 数据 curate 耗时超预期 | 中 | 中 | 砍数量保质量（30 家+20 组够 Spike）；优先高频品类 |
| 前后端联调延期 | 中 | 中 | API 契约先行，P1 用 mock 并行开发 |
| 买家招募不足 5 人 | 中 | 高 | P5 Day 1 即启动多渠道（校友/社群/1688 买家群/冷启） |
| DashScope 接入/限流 | 低 | 中 | 提前测通；.env 可切其他 OpenAI 兼容模型；结果缓存 |
| 多存储一致性（MySQL/Neo4j/Milvus） | 中 | 中 | MySQL 为事实源，Neo4j/Milvus 异步同步并标注时间 |
| 关键路径单点（P3） | 中 | 高 | P5 兼懂 AI 可支援；智能体接口清晰便于分工 |
